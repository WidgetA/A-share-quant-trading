# Web 交易通道切换

## 位置和范围

首页“交易连接”和设置页提供 miniQMT / QMT 下拉选择及“切换”按钮。
默认使用原 miniQMT 配置。选择保存在服务端，重启后恢复；切换前检查目标通道，
不可用时保留原选择，不自动切往另一通道。切换同时清除原通道的账户、持仓、委托缓存。

本次基于 `refactor/cleanup-v15-only` 的 `0c16775` Web 交易实现开发，
独立工作树为 `A-share-quant-trading-qmt-switch`。已核对远端 `main` 的 `bd2fbe4`；
其 V22 通知服务不是此 Web 交易模块。本次没有修改 V22 选股任务或覆盖研究数据。

## 配置

- miniQMT 沿用设置页原有 URL 和 API Key。
- QMT 填写 `client.secret` 中的 HTTPS 源地址、实例 ID、密钥标识、签名密钥，
  通过文件选择框上传电脑上的 CA 证书，不需要填写路径或手动挂载证书。
  支持 PEM/DER 格式的 `.pem`、`.crt`、`.cer` 公钥证书，最大 64 KB，不接收私钥。
  测试或保存时自动上传；不选择新文件则保留原证书。可明确勾选“使用系统信任证书”
  并保存，恢复系统证书。TLS 和主机名验证始终开启。
- “测试连接”只查询账户及交易状态，不启用交易。只读实例可查询资金与持仓，
  下单仍受代理原有授权及政策约束。保存 QMT 配置后，点击“切换”使它生效。
- 密钥不会从状态接口返回，也不会预填到浏览器。填写新密钥后保存，输入框清空；
  地址、实例和密钥标识未改变时，密钥留空表示保留原值。

Web 配置和原请求存放于 `data/trading-channels.sqlite3`，包含连接凭据。
该文件位于 Git 忽略的数据目录；部署必须持久挂载 `data`，限制文件访问并按凭据管理备份。
上传的 CA 保存在 `data/qmt-certificates/`，与配置一起持久化。文件名由证书内容生成，
不使用上传文件名；更换证书不会覆盖原通道的证书。已有配置中的旧证书路径继续可用，
页面仅显示是否已保存证书，不返回服务器路径。
历史连接配置用于原订单查询和撤单，不因切换清除。当前 Web 部署使用单应用进程；
不得增加多个独立实例并让它们共享同一交易入口而不设计配置同步及统一存储。

## 接口与状态

新增接口受现有 Trading API Key 规则保护：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/settings/trading-channel` | 当前通道、通道标识及不含密钥的配置 |
| POST | `/api/settings/trading-channel` | `{"backend":"miniqmt"}` 或 `{"backend":"qmt"}` |
| POST | `/api/settings/trading-channel/qmt` | 保存 QMT 配置 |
| POST | `/api/settings/trading-channel/qmt/ca` | multipart 字段 `file` 上传 CA，返回证书标识 |
| POST | `/api/settings/trading-channel/qmt/test` | 仅通过签名 GET 测试 QMT |

QMT 配置正文：`url`、`instance_id`、`key_id`、`secret`；上传新证书后附加
`ca_certificate_id`。省略证书标识保留原证书；`use_system_ca=true` 明确改用系统证书。
保存和测试均使用上传证书；测试不会更改已保存配置或当前交易通道。
现有买入、卖出、批量买入路径保持，浏览器附加 `request_id` 和 `channel`。
同一次请求的网络重试保留这两项及原内容；新的明确操作使用新编号。
QMT 请求缺少编号会被拒绝。未升级的 miniQMT 调用方仍可按旧格式调用。

普通 QMT 订单走 `/v1/trading/orders`；取消走 `/v1/trading/cancels`，
取消后查询 `/v1/trading/commands/{cancel_id}`。签名和发送使用相同的 JSON 字节，
每次 HTTP 使用新时间戳/nonce，不调用管理启用接口，不降级到历史 paper 路径。

请求意图和通道先持久化再发送。重复编号通过原通道查询，不能因为切换而重新下单；
超时、响应异常、503 或提交后的 404 不触发重发。原提交错误保留在账本，查询错误不覆盖它。
委托列表的 `cancel_id` 包含原通道归属，撤单调用方必须原样传入，不能只取券商数字编号。
QMT 账户快照里的其他来源委托可查看，不冒充本 Web 订单，也不能经本 Web 撤销。

“代理已接收”“等待券商回报”“全部成交”分别展示。未知成交数量保留 `null`；
部分成交后撤销仍保留实际成交股数。一次查询失败保留已观察事实。
快照必须属于当前入口会话、账户已观察，且更新时间在当前时间之前 30 秒以内。
无快照或过期时显示数据不可用；不展示为零账户。

## 能力差异

- 单只买入支持现有的指定价格，卖出沿用市价委托；QMT 只支持该代理声明的沪深证券范围。
- miniQMT 批量买入保留原重试及余量限价规则。
- QMT 批量买入按金额和参考价换算整手股数，对每只提交一次普通市价委托。
  页面在确认前说明这一行为，不自动补单或把余量转限价；结果逐只展示，受理不算成交。
- QMT 持仓成本读取代理返回的 `avg_price`（源自券商 `m_dOpenPrice`）。未返回成本和冻结资金时展示未知。
  零/负成本按券商原值展示，成本不大于零时不计算盈亏百分比。
  QMT 原始意图、查询状态及成交结果保留在独立通道账本。
  原交易笔记没有账户维度，因此 QMT 不导入该旧笔记，也不使用其历史重建 QMT 净值。
  未关联的 QMT 实例独立记录净值。用户确认 QMT 与 miniQMT 为同一资金账号后，
  服务端持久保存明确的账户关联，后续查询和写入沿用原账户 ID，不搬动或删除历史快照。
  关联绑定 QMT 地址及实例，更新证书或密钥不丢失；其他实例不自动继承。
  订单标识、重试和撤单仍按原交易通道隔离。
- 本开关只切换交易与账户请求。Tushare 行情及选股任务不因切换改变。
