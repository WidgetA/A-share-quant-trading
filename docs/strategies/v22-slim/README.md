# V22-slim

用户于 2026-09-11 授权以 V22-slim 替换线上 V20 的选股部分。

范围：冻结 V22 的 09:30–09:39 十根输入、固定模型与排序、完整
BASE × rolling7/G → H90 → D0-N2 开仓判断、原 Top3 推荐。
完整 Top10 继续作为参考组合；阻断时明确显示不新开仓。
放行表示使用当天分配资金份的全额，不表示全账户满仓。

复用现有 V20 的独立运行资源、调度、持久化和推送通道，替换策略计算。
V16 保持独立。此次不实现 V22 卖出策略、账户资金管理或自动下单。
既有 V20 批次的退出提醒保留原规则与版本归属。

迁移保存冻结状态来源及原始输入证据，不能把旧 V20 空初始状态当作
冻结 V22 连续风险状态。历史输出仅作离线验证；生产使用正式资产、
原始行情与持久参考状态，不导入 research 或读取历史开仓表。

验收：本周冻结选股与开仓逐日对照、H90/D0 边界、时点与缺数据、
重启与重复执行、手动/自动一致、V16 隔离、Top3 与阻断消息。
部署后核对线上版本、启动健康和原入口，不以 CI 成功代替上线验收。

默认启动入口已切换到 `config/v22-slim.yaml`，继续使用原 `/api/v20/*`
和推送路由。切换点为 2026-09-11 收盘，首个新交易日槽为 2026-09-14。
周五既有 V20 决策不可改写；手动重放旧 V20 槽不会发布新的 V22-slim 建议。
手动验收必须能够按当前 V22-slim 口径独立重算并推送核查结果。
旧版本正式快照只保留原归属，不作为新版本原始输入必须相同的断言；
同版本重放仍严格校验已封存输入。核查结果及完整计算快照持久化到操作事件，
不改写旧正式槽、正式状态或仓位。按目标日选择严格早于该日的状态种子，
不得使用当天收盘后的状态重算当天早盘。
自动放行仍原子保存正式决定、参考组合和推送事件，但 V22-slim 不创建卖出批次；
存储层按显式版本及 `entry_only` 合同校验，不沿用 V20 的强制建批次条件。
运行模式沿用现有 `forward_shadow`。`/api/status` 的 `v20.strategy_version`
应为 `V22-slim`，`entry_only` 应为 `true`；镜像提交和启动健康须同时核验。

已完成离线验收：9 月 7–10 日完整 Top10、全部推荐分数一致；
完整开仓链条逐日一致，分别为 ENTER、BLOCK、BLOCK、NO_SIGNAL。
风险计数为 14→0→1→2→2，H90 比值和各层输入一致。
周五收盘补齐后风险计数为 3，保存在带哈希校验的正式状态种子中。
种子包含 20 日全市场早盘金额、已成熟纸面标签和未成熟完整参考组合。
后续每天由原始行情推进；重启不清零，重复计算复用同一已封存状态。

源缺失或中间交易日没有可验证的 V22-slim 参考状态时，明确报错并不开仓，
要求补齐参考状态后恢复，不能跳过该日或重新初始化。
本次不加入 AI 硬件板块排除规则，也不重训模型或改动冻结阈值。

离线复核脚本为 `scripts/verify_v22_slim_week.py`（选股）、
`scripts/verify_v22_slim_gates.py`（状态与开仓）和
`scripts/verify_v22_slim_canonical.py`（实际计算入口与重启）。
这些脚本需要原研究工作区或本地采集证据；生产模块不依赖它们。
