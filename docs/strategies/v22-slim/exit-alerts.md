# V22 卖出告警与人工校准

依据 2026-09-13 用户确认：“按放行前 3 只记录，可人工校准”。

每天首次放行 Top3 在完整选股任务的同一数据库事务中登记。自动任务和按钮共用此处；
同日新请求仍重算选股，但不重复记持仓，不覆盖人工校准。不放行或实时无数据不登记。
从本功能部署后的新结果开始记录，不把历史推荐自动补成实际持仓。

初始成本取推荐日 raw 09:41 分钟 open；该分钟尚未取得时成本保持待取得。
未校准时明确标注策略参考价、数量未知。人工可修改成本、剩余股数、买入日期，
或标为未买入、已卖完。每次校准保存前后值，并使用版本号防止旧页面覆盖新修改。

退出仅发告警：按交易所交易日从买入日递推，当天不卖；第 1 个交易日成本止损 8%，
第 2 个交易日止损 12%。原第 1 个交易日 09:40 前已经接收、封存并可用的 MEWS
为 DANGER 时，第 2 个交易日收紧到 5%；缺失沿冻结兼容口径使用 12%，不伪称 NORMAL。
止损用有效已完成分钟的收盘价，不用分钟最低价或阈值虚构成交价。

第 1 个交易日另检查冻结 R33_B：连续两根走弱、连续两根恢复净盈利、连续两根
再跌破短均线和日内成交均价，提醒卖出剩余全部。午休、缺根、未知输入重置阶段；
异常量价对使当天后续 VWAP 不可用。EMA、ATR、价格链和净费用阈值沿冻结 V22 规范。

第 2 个交易日 14:57 发计划卖出提醒；只有 14:56 的 237 根完整规定前缀及前三根
真实日 K 按冻结蜡烛图完整分类为 STRONG 才延到下个交易日。缺数据不判强势。
已触发的风险提醒不被强势取消，已经保存的强势延持不因重启后补数改写。
延持结束在下一交易日首根有效完成分钟提醒；告警时间不等于历史回测开盘成交代理。

所有行情使用服务自身的行情客户端：当天 rt_min_daily，完成历史日 stk_mins；
当天实时为空不回退历史接口。重启可恢复尚未处理持仓的历史退出条件，消息显示真实
信号日期时间。只请求持仓个股，不另起全市场采集。既有 V20 退出规则保持原归属。

首个退出提醒原子保存到现有 outbox，经同一生产飞书投递器发送。未封存事件由现有
恢复任务补封存；重复扫描不新建同一提醒。外部回执未知保留 DELIVERY_UNKNOWN。
提醒发出后记录仍保留持仓；不自动下单、不假定成交，也不重复发送后续同类卖出提醒。
已发出的提醒不能撤回；之后的人工校准保存实际余量，不改写历史消息。

接口沿现有 `/api/v20` 路由，使用 `X-V20-API-Key`（服务端 V20_INGEST_API_KEY）：

```http
GET /api/v20/v22-positions
X-V20-API-Key: <配置的密钥>
```

从列表取得 `position_id` 和当前 `revision`，然后提交要修改的字段：

```http
POST /api/v20/v22-positions/<position_id>/calibrate
X-V20-API-Key: <配置的密钥>
Idempotency-Key: correction-20260914-001
Content-Type: application/json

{"expected_revision": 1, "entry_price": 25.60, "quantity": 400}
```

未买入用 `{"expected_revision": 1, "status": "NOT_BOUGHT"}`；已卖完用
`{"expected_revision": 1, "quantity": 0}`，部分卖出则填实际剩余股数。
同请求编号网络重试返回同一结果；新修改使用新编号。版本过期返回 409，先重新读列表。
未提供字段保留原值；修改买入日期后，非人工成本重新取对应日参考价。

验证位置：`tests/unit/web/test_v22_exit_alerts.py`；真实 PostgreSQL、两个选股入口、
校准防覆盖、告警落库/封存/飞书投递器验证并入 `test_v20_outbox_postgres.py`。
CI 镜像发布依赖这些检查。线上是否实际送达须以具体提醒事件的 SENT 回执为准，
不能用健康接口、空持仓查询或模拟投递通过宣称实际提醒已送达。
