# realtime 空数据回归记录

依据用户最后的明确要求：直接取 realtime 当前数据，不额外判断周末/节假日，不把当天
回退到周五；接口没有可用数据，就不出票。此前拟定的“按日历阻止取数”检查已撤销。

修复前生产提交：`b79a562669c8e49edd5c98e52b6a69cc5dbbb63d`。
先提交测试 `a60be82`，再修改实现。测试使用实际 Tushare 客户端与解析器，远端响应、
历史特征和数据库使用受控输入；任务、日期选择、分钟接口选择和空结果处理使用生产代码。

修复前结果：2 failed, 7 passed。

- 周六：定时入口在日历判断处退出，没有请求 realtime；手动入口则会回退到周五。
- 工作日空数据：realtime 返回空数据后仍继续后续流程，未在输入为空处结束。

修复后的检查要求两个入口都调用 `rt_min_daily`，没有历史分钟请求参数，不选出股票、
不保存或封装选股推送。当前提供商分钟内复用原有单次获取机制，传输错误仍按错误处理。

本记录是回归证据，不能替代部署后的实际当前接口调用。空数据路径不要求选股消息送达，
因为它本来就不应产生票单或选股推送。
