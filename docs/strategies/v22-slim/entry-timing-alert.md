# V22-slim 入场时点提醒

2026-09-23 用户要求以新增消息方式上线此前倒推介入规则：“在推票的时候多推一条告警，先说今天可以考虑不在开盘进，然后再把票面的list推出来”。

## 触发条件

原 V22-slim 放行的计划买入股票（最多三只），在上证指数 9:40 低于昨收时，分别判断：

- 原始 09:30—09:39 十个分钟收盘价中，任意间隔 1—3 分钟的最大跌幅 >1.61%，且这十分钟成交额 ≤4.18 亿元；或者
- 最大跌幅 ≤1.61%，且 09:37—09:39 成交额 / 十分钟总成交额 >36.47%。

有命中股票才多发一条告警，标明股票代码和名称。未命中仍发送原列表。不放行或无票不生成该等待告警。
这只是介入时点提醒，不替用户成交，不改变原选股、放行、自动暂记持仓、资金比例和退出通知规则，也不新增下午定时通知。

## 数据与时间

个股特征使用本次完整选股任务的同一份当前实时分钟事实，参数固定，不在生产拟合。
特征暂存于本次计算对象，判断所用数值及指数来源保存在运行的 `entry_timing_advisory` 中；原冻结选股快照格式保持兼容。

指数优先使用 Tushare `rt_idx_min_daily` 的当日唯一 09:40 行，昨收来自前一交易日的 `index_daily`。
生产账号目前没有该指数实时分钟接口权限，因此当前日取数可以使用腾讯公开的当日上证分时作为备用。
备用源必须验证指数代码、当前交易日期、唯一 09:40 标签和有效价格，不能拿最新价格或其他交易日替代。
Tushare 与腾讯的分钟取样存在差异，不声明数据逐值等价；运行证据记录实际供应商及数值。
验证样例 2026-09-23：腾讯 09:40 为 3947.59，Tushare 为 3947.679；二者当天都低于昨收。
Tushare 指数实时接口说明：https://tushare.pro/wctapi/documents/420.md。

若计算在 09:40 前完成且有个股命中等待条件，需要等待 09:40 指数事实；该标签暂未返回时做有限实时重试。
不可用则保存 `UNAVAILABLE` 及原因，不伪造绿盘或等待命中；原股票列表继续按原规则处理。
历史验证只对已完成交易日使用 `idx_mins`，不用于线上当天的替代取数。

## 消息顺序与回执

完整任务在同一事务保存运行结果、告警消息和股票消息。告警有独立事件编号、封存内容、投递尝试与回执。
告警确认 `SENT` 后，对应股票消息才可被投递器取走；单靠插入先后顺序不保证发送顺序。
同请求编号重试复用同一对消息，新按钮点击重新取数、计算并产生本次消息，每日状态和暂记持仓仍只推进一次。
按钮响应分别显示告警和票单状态，必要消息均确认送达才算完成。未知回执不当作成功。

## 验证

新增共享任务行为检查先在原实现失败：定时及按钮路径都缺少告警判断，重试只封存票单、没有封存告警。
新增文案检查先在原实现失败：旧 DATA_ALERT 渲染成系统异常消息，没有用户要求的首句。
规则边界、实时源日期、取消行为、定时/按钮一致、重试恢复与消息文案单测纳入 Selection Task Contract。
真实 PostgreSQL 检查覆盖事务回滚、消息依赖、两条独立回执、未知投递、不同运行以及 scope 隔离；镜像发布依赖这些检查。
